# Роль

Ты — опытный full-stack разработчик, специализирующийся на PWA, Firebase и мобильных веб-приложениях.
Проект пишем на Vue 3 Composition API и TypeScript(<script setup lang="ts">), стили на Tailwind.

# Задача

Разработать прогрессивное веб-приложение (PWA) для учёта питания. Приложение должно позволять пользователю ежедневно вносить данные по четырём показателям: белки, жиры, углеводы, калорийность.
При внесении данных по белкам, жирам и углеводам калорийность считается автоматически по формуле:
калории = 4 _ белки(г) + 4 _ углеводы (г) + 9 \* жиры (г)
и вносится в поле калорийность. При этом пользователь может и сам внести данные в поле калорийность.
Данные должны сохраняться, суммироваться и отображаться в информационных компонентах 'сегодня', 'за неделю', 'за месяц'.

Приложение должно поддерживать множество пользователей (до 100 человек) с полным разделением данных. Каждый пользователь авторизуется один раз и остаётся в системе автоматически при повторных открытиях. Приложение должно устанавливаться на iPhone через функцию «На экран «Домой»» и работать офлайн.

# Технологический стек

Frontend: проект пишем на Vue 3 Composition API и TypeScript(<script setup lang="ts">), стили на Tailwind.
Backend + БД: Firebase (Authentication + Firestore)
Хостинг: Firebase Hosting
PWA: manifest.json + Service Worker

# Функциональные требования

1. Авторизация

- Страница входа/регистрации с email и паролем.
- После успешного входа пользователь не должен вводить пароль повторно при перезагрузке страницы или повторном открытии приложения.
- Кнопка «Выйти» очищает сессию.

2. Главный экран (после входа)

- Форма для ввода: белки (г), жиры (г), углеводы (г), калории (ккал).
- Кнопка «Добавить» сохраняет запись в Firestore с привязкой к текущему пользователю, текущей дате и времени.
- Под формой - информационная панель с внесенными записями за сегодня с указанием времени с возможностью удалить каждую запись.
- Затем идут три информационных панели с суммированными значениями - за сегодня, за текущую неделю (с понедельника по воскресенье), за текущий месяц.

3. Разделение пользователей

- Все данные в Firestore должны храниться с полем userId.
- Запросы на чтение/запись должны фильтроваться по userId.
- Правила безопасности Firestore должны разрешать доступ только авторизованным пользователям и только к своим данным.

4. PWA для iPhone

- Приложение должно устанавливаться на экран «Домой» на iOS (Safari).
- Должен быть manifest.json с иконками (хотя бы 192x192 и 512x512).
- Должен быть Service Worker (sw.js), кеширующий основные файлы для офлайн-работы.
- Адаптивный дизайн.
- Макет примерной верстки - в папке 'requirements/' в файле 'layout.png' или 'layout.pdf' (скажи, какой формат лучше для тебя?)

# Технические требования к коду

- Firebase SDK подключается через CDN (ES modules).
- Код должен быть готов к деплою через firebase deploy без дополнительных сборок.

# Правила безопасности Firestore

- Только авторизованные пользователи имеют доступ.
- Чтение/запись записей (entries) только если userId == request.auth.uid.
- Чтение/запись профиля (users) только если userId == request.auth.uid.

# Дополнительные пожелания

- Код должен быть самодостаточным: нужно только заменить firebaseConfig на свои данные из консоли Firebase.
- Добавить комментарии в необходимых местах.
- Интерфейс должен быть удобным для ежедневного быстрого внесения данных (крупные поля, минимум кликов).
